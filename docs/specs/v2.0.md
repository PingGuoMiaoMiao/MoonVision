# MoonVision v2.0 Specification

## Summary

`v2.0` moves MoonVision from a competition-ready lightweight image-processing library into a broader lightweight `imgproc` layer for MoonBit.

This version must stay aligned with the existing project boundary:

- MoonBit-native implementation.
- No OpenCV binding.
- No GUI.
- No video pipeline.
- No DNN or machine-learning model integration.
- No medical-diagnosis claim for bacteria examples.

`v2.0` focuses on the next practical OpenCV `imgproc` gaps that fit MoonVision's current architecture:

- histogram analysis and histogram equalization;
- extended morphology operators;
- distance transform for binary masks;
- Hough line detection for simple edge maps;
- template matching for grayscale images;
- bilinear resize for better geometric preprocessing;
- documentation and demo updates that explain the new scope clearly.

## Goals

- Improve MoonVision's coverage of lightweight `imgproc` concepts without trying to replicate full OpenCV.
- Add algorithms that are useful for object counting, edge analysis, document preprocessing, and labeled-image review.
- Keep APIs small, explicit, and testable.
- Preserve compatibility with the existing `v1.5` public API where practical.
- Keep generated images, CSV files, and HTML reports out of version control.

## Non-Goals

- No full OpenCV replacement.
- No OpenCV source-code port.
- No GPU acceleration.
- No SIMD-specific backend work.
- No feature-point framework such as ORB, SIFT, SURF, or descriptor matching.
- No camera calibration or 3D reconstruction.
- No video read/write.
- No GUI windowing.
- No automatic bacteria diagnosis model.
- No large abstract image-processing graph framework.

## Scope

### 1. Histogram Module

Add a new lightweight histogram capability for `GrayImage`.

Required public capabilities:

- compute a 256-bin grayscale histogram;
- compute cumulative histogram;
- normalize histogram counts for reporting;
- equalize grayscale image histogram;
- export histogram summaries for demo/report use.

Constraints:

- first version is grayscale only;
- no RGB histogram;
- no HSV histogram;
- no histogram comparison API in this version;
- no back projection API in this version.

Validation focus:

- fixed small images produce exact bin counts;
- cumulative histogram is monotonic;
- equalization preserves image size;
- equalization maps constant images safely;
- equalization expands simple low-contrast fixtures.

### 2. Extended Morphology

Extend the existing binary morphology package while keeping the current erosion/dilation/opening/closing behavior stable.

Required public capabilities:

- morphological gradient;
- top hat;
- black hat;
- configurable iteration count for existing binary operations;
- basic structuring-element selection for square and cross kernels.

Constraints:

- first version remains binary-mask focused;
- no grayscale morphology in this version;
- no arbitrary user-defined kernel matrix in this version unless it fits the existing package cleanly;
- current `erode`, `dilate`, `open_binary`, and `close_binary` behavior must not silently change.

Validation focus:

- gradient highlights binary boundaries;
- top hat extracts small bright foreground regions removed by opening;
- black hat extracts small dark holes filled by closing;
- iteration count behaves the same as repeated calls;
- square and cross kernels produce different results on diagonal fixtures.

### 3. Distance Transform

Add a binary distance transform for simple mask analysis.

Required public capabilities:

- compute approximate distance-to-background for foreground pixels;
- support at least Manhattan distance;
- optionally support chessboard distance if it does not complicate the API;
- provide maximum-distance helper for object-center style analysis.

Constraints:

- output can be an integer gray-style distance image or explicit distance map type;
- no floating-point Euclidean transform in the first version;
- no watershed in this version unless separately specified later.

Validation focus:

- isolated pixel has distance `1`;
- rectangle center has larger distance than boundary;
- empty foreground produces all-zero distance;
- full foreground with border handling is deterministic.

### 4. Hough Line Detection

Add a minimal Hough line detector for binary edge maps.

Required public capabilities:

- accept binary `GrayImage` edge map;
- return line records with rho, theta bucket, and vote count;
- allow vote threshold;
- allow maximum number of returned lines;
- sort returned lines by vote count.

Constraints:

- no probabilistic Hough transform in this version;
- no Hough circle detection in this version;
- no subpixel line refinement;
- no automatic Canny step inside the API.

Validation focus:

- horizontal fixture returns a strong horizontal line;
- vertical fixture returns a strong vertical line;
- empty edge map returns no lines;
- threshold filters weak lines;
- output ordering is deterministic.

### 5. Template Matching

Add a small grayscale template matching module.

Required public capabilities:

- slide a grayscale template over a grayscale source image;
- support sum of absolute differences as the first scoring method;
- return best match location and score;
- optionally return a score map if it can be represented without expanding the public API too much.

Constraints:

- grayscale only;
- no scale-invariant matching;
- no rotation-invariant matching;
- no multi-template batch API;
- no normalized cross-correlation unless it is introduced in a later spec.

Validation focus:

- exact embedded template is found at the expected coordinate;
- template larger than image returns an error;
- repeated identical matches resolve deterministically;
- score improves when the image region is closer to the template.

### 6. Bilinear Resize

Extend geometric transforms with bilinear interpolation.

Required public capabilities:

- resize `GrayImage` using bilinear interpolation;
- preserve existing nearest-neighbor resize API;
- validate positive output dimensions.

Constraints:

- grayscale only in this version;
- no bicubic interpolation;
- no area interpolation;
- no arbitrary remap.

Validation focus:

- output size is exact;
- resizing to same dimensions preserves values;
- simple 2x2 to larger image produces interpolated interior values;
- invalid dimensions return the existing error style.

### 7. Demo and Documentation Updates

Update docs and demos only where they make the new capabilities understandable.

Required updates:

- README mentions `v2.0` capabilities;
- `docs/opencv-gap-analysis.md` is updated with reduced `imgproc` gaps;
- add one focused `v2.0` demo path or extend existing demos with clearly named outputs;
- avoid committing generated output files;
- document which commands validate the new version.

Preferred demo direction:

- document enhancement uses histogram equalization or bilinear resize where it is visually meaningful;
- edge detection or object counting can expose Hough line or morphology-gradient output;
- bacteria review remains focused on reporting and should not become the main `v2.0` algorithm target.

## Public API Style

- Keep pure-function style first.
- Use existing `ImageError` behavior where applicable.
- Avoid implicit pipelines that combine thresholding, filtering, contouring, and matching in one high-level call.
- Add small modules only when the concept is distinct enough from existing modules.
- Keep names descriptive and stable.

Expected module additions:

```text
src/histogram/
src/transform/ or existing src/image/
src/shape/ or existing src/components/
src/match/
```

Before implementation, exact module placement must be decided by inspecting current package dependencies and minimizing import cycles.

## Implementation Slices

The implementation should be split into 8-12 meaningful commits:

1. `v2.0` spec and acceptance scope.
2. Histogram counts and cumulative histogram with tests.
3. Histogram equalization with tests.
4. Extended morphology operators with tests.
5. Distance transform with tests.
6. Hough line records and detector with tests.
7. Template matching with tests.
8. Bilinear resize with tests.
9. Demo update with generated outputs kept ignored.
10. README and OpenCV gap document update.
11. Final validation fixes.
12. Final `v2.0` verification document if needed.

Each commit must have one primary purpose. Do not split commits by meaningless line count.

## Validation Plan

Core validation:

```powershell
moon check
moon test
```

Existing demo validation:

```powershell
moon run src/demo/object_counting
moon run src/demo/edge_detection
moon run src/demo/document_enhancement
```

Optional bacteria-review smoke validation:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_labeled_bacteria_review.ps1 -SampleFolders 346 -ExcludeRenameCopies
```

New `v2.0` validation must include:

- histogram fixtures;
- morphology extended fixtures;
- distance transform fixtures;
- Hough line fixtures;
- template matching fixtures;
- bilinear resize fixtures;
- at least one visual demo output path documented in README.

## Acceptance Criteria

`v2.0` is complete only when:

- all new algorithm APIs have focused unit tests;
- existing `v1.5` tests still pass;
- existing three demos still run;
- new or upgraded demo output is documented;
- README reflects `v2.0`;
- OpenCV gap document is updated;
- generated images, CSV files, and HTML reports are not committed;
- repository branch is pushed to GitHub.

## Risks

- Hough line detection can become expensive if accumulator size is too large.
- Template matching is naturally slow with naive sliding windows on large images.
- Histogram equalization can over-amplify noise on real low-light images.
- Extended morphology can create confusing semantics if binary and grayscale morphology are mixed too early.
- Adding too many OpenCV-like APIs at once would weaken the lightweight positioning.

## Deferred Items

These are deliberately not included in `v2.0`:

- Hough circle transform;
- watershed;
- Euclidean distance transform;
- RGB histogram;
- histogram comparison;
- back projection;
- affine transform;
- perspective transform;
- remap;
- bicubic resize;
- full drawing API;
- video and camera I/O;
- machine-learning or DNN inference.
